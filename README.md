# Stackat support

Questions, problems and ideas about [Stackat](https://stackat.dev) go here. We read everything.

| You want to | Go to |
| --- | --- |
| Ask how something works, or whether Stackat fits your setup | [Discussions → Q&A](../../discussions/categories/q-a) |
| Report something broken (dashboard, scans, issues, pull requests, Slack, Jira link) | [New issue → Bug](../../issues/new?template=bug.yml) |
| Tell us an issue was wrong, or missed a change that broke your upgrade | [New issue → Wrong or missed finding](../../issues/new?template=finding.yml) |
| Suggest a tool to cover, or a feature | [New issue → Feature request](../../issues/new?template=feature.yml) |
| Report a security problem | **Not here:** see [SECURITY.md](SECURITY.md) |
| Anything private: billing, your account, deleting your data | Email [info@progrex.dev](mailto:info@progrex.dev) |

**This repository is public.** Don't post private repository names, file contents, secrets or anything you would not
put on the internet. When a report needs those, open the issue without them and say so: we follow up by email.

**On a Stackat issue in your own repository** you can also reply right there: `/stackpaw wrong …`, `/stackpaw missed …`
or `/stackpaw note …` reaches the Stackat team with the issue attached, and stays in your repository.

## Before you ask

- [Documentation](https://docs.stackat.dev): getting started, how issues are laid out, `.stackat.yml`, commands, Slack, plans.
- [Troubleshooting](https://docs.stackat.dev/troubleshooting/): no issues yet, a tool not found, settings not picked up.
- [The public demo](https://github.com/self-maintaining-api/demo-homelab-k3s): a real cluster where Stackat works in the open.

## What happens next

We answer on working days (Central European Time). A confirmed bug gets the `confirmed` label and a comment when the
fix is live; a wrong or missed finding is checked against the release notes and, when we got it wrong, the fix goes
into the matching for everyone.
